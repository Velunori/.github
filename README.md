# Velunori organization profile

[`profile/README.md`](profile/README.md) is displayed on [github.com/Velunori](https://github.com/Velunori).

The suite, installation script and user documentation live in [Velunori/velunori](https://github.com/Velunori/velunori).

## Shared community files

- [Contributing](CONTRIBUTING.md): repository routing, development setup, validation and PR guidance.
- [Support](SUPPORT.md): help and issue routing.
- [Security](SECURITY.md): private vulnerability reporting and maintenance policy.
- [Code of Conduct](CODE_OF_CONDUCT.md): behavior and moderation expectations.
- [Issue forms](.github/ISSUE_TEMPLATE): bug reports, installation problems, improvements, questions and new-plugin proposals.
- [Pull request template](.github/PULL_REQUEST_TEMPLATE.md): change description and validation evidence.

These are organization defaults, inherited by repositories without their own corresponding files. GitHub requires issue forms inside `.github/ISSUE_TEMPLATE` even in this `.github` repository. A repository with its own issue forms or chooser configuration overrides the entire shared issue-template set. See [GitHub's default community file documentation](https://docs.github.com/en/communities/setting-up-your-project-for-healthy-contributions/creating-a-default-community-health-file).

Keep shared links absolute so they work from every inheriting repository. Private vulnerability reporting must be enabled separately in repository settings; publishing `SECURITY.md` does not enable it. Licenses and repository-specific automation are not inherited from this repository.
